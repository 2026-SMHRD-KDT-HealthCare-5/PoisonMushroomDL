독버섯 분류 프로젝트 - 기존 기획서 대비 변경사항 정리
(기준 문서: 독버섯분류_기획서.pdf, 빅데이터분석정의서_독버섯.pdf)

====================================================================
1. 분류 대상 및 접근 방식 변경 (가장 큰 변경)
====================================================================

[기존 기획서]
- 외형이 유사한 독·식용버섯 6쌍(12클래스) 분류
  예) 노란다발버섯-개암버섯, 화경버섯-느타리/표고,
      삿갓외대버섯-외대덧버섯, 마귀광대버섯-붉은점박이광대버섯 등
- 목표: 육안 구분이 어려운 "닮은꼴 쌍"을 fine-grained 분류로 구분

[변경]
- 닮은꼴 쌍(lookalike-pair) 비교 접근은 전면 폐기
- CV는 독버섯 7종 자체를 직접 분류하는 방식으로 전환
  (마귀광대버섯, 개나리광대버섯, 삿갓외대버섯, 화경버섯,
   노란개암버섯, 독우산광대버섯, 붉은사슴뿔버섯)
- 관련 코드/데이터/문서에서 식용버섯 짝 비교 요소 전부 제거

====================================================================
2. RAG(챗봇) 검색 범위 확장
====================================================================

[기존 기획서]
- "예측된 종 -> 생태도감 텍스트에서 독성.증상 정보를 FAISS로 검색 -> LLM 정리"
  라고만 되어 있어, RAG 대상이 CV가 분류하는 종(12클래스)에 한정된 구조

[변경]
- RAG/챗봇의 검색 대상을 도감 수록 194종 전체로 확장
- CV(7종)와 RAG(194종)의 역할을 분리:
  - CV: 7종만 이미지 분류
  - RAG: 194종 전체에 대해 자유 질의응답 가능
- 처리 방식은 하이브리드 구조로 설계
  - CV 대상 7종: 미리 파싱해 mushroom_db에 저장 (예측 직후 즉시 응답)
  - 나머지 187종: 챗봇이 해당 종을 언급할 때 그 자리에서 실시간 검색/파싱
    (search_species_by_name 함수)

====================================================================
3. 생태도감 PDF 페이지 매핑 로직 재설계
====================================================================

[기존 기획서/초기 노트북]
- "찾아보기(VII, p.656~) 섹션을 파싱해 {종명: 페이지} 매핑 생성"
- "한 PDF 페이지에 좌/우 2종이 함께 들어있다"는 전제로 파싱
  (split_two_species / get_species_info)

[변경 - 실제 PDF 구조 확인 후]
- 목차(PDF 인덱스 6): 자동 파싱 시도했으나 실패 -> 수동 딕셔너리로 확정
- 종 목록(인쇄 페이지 68~73): 194종 전체의 {국명: 페이지} 매핑을
  자동 파싱으로 새로 생성 (species_page_index_full)
- 종 설명 본문(인쇄 페이지 74~461): 기존 가정("한 페이지 2종")이 틀렸음을 확인.
  실제로는 "한 종이 2페이지 차지" 구조 -> 전용 파서 get_species_info_v2 신규 작성
- 찾아보기(656~) 및 506~649페이지 구간: 사용하지 않기로 확정, 관련 코드 폐기

4. 응급처치/독성 정보 처리 방식 변경
====================================================================

[기존 기획서]
- "필수 출력 고지: 이상 증상 시 즉시 의료기관에 문의하십시오" 정도의
  고정 문구만 언급, 종별 세부 응급처치 정보 획득 방법은 미정
- 초기 노트북: 독성 랭크.응급처치를 "도감 다른 섹션(p.12, p.27)을 참고해
  수동으로 채워 넣기"로 계획 (MANUAL_SUPPLEMENT)

[변경]
- 목차에서 "중독유형별 치료방법" 섹션 위치를 확인(인쇄 페이지 27~33)
- 해당 구간 원문을 LLM(Gemini)에 전달해
  {중독유형: {rank, emergency_action}} 형태로 자동 구조화
- 각 종의 원문 중독정보 블록(raw_toxicity_block)과 매칭시켜
  7종에 자동 반영 (apply_treatment_info)
- 수동 입력(MANUAL_SUPPLEMENT) 방식은 폐기

요약
====================================================================
프로젝트의 핵심 축이 "닮은꼴 쌍(12종) 이미지 분류 + 해당 종 RAG 안내"에서
"독버섯 7종 직접 분류(CV) + 도감 194종 전체 대상 RAG 챗봇(하이브리드 구조)"로
전환되었습니다. 이에 따라 PDF 페이지 매핑 로직 전면 재설계, 응급처치 정보
자동화(LLM 기반)가 함께 진행되었습니다.
